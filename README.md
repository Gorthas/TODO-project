# TODO Scheduler

## О проекте

Учебный дипломный проект курса Яндекс Практикума «Go-разработчик с нуля»

TODO Scheduler — веб-планировщик задач с сервером на Go и хранением данных в SQLite. Приложение позволяет создавать, просматривать, искать, редактировать, выполнять и удалять задачи, а также поддерживает повторяющиеся задачи

Фронтенд предоставлен курсом и раздаётся самим Go-сервером из директории `web`

## Возможности

* создание задач с датой, заголовком, комментарием и правилом повторения;
* просмотр списка ближайших задач с сортировкой по дате;
* поиск задач по заголовку, комментарию или конкретной дате;
* просмотр и редактирование существующих задач;
* отметка задачи как выполненной;
* удаление задач;
* автоматический расчет следующей даты для повторяющихся задач;
* хранение данных в SQLite

Для повторяющихся задач поддерживаются правила:

* `d N` — повторение через `N` дней, где `N` от 1 до 400;
* `y` — ежегодное повторение;
* `w` — повторение в указанные дни недели;
* `m` — повторение в указанные дни месяца и, при необходимости, только в выбранные месяцы

Если правило повторения отсутствует, выполненная задача удаляется. Для повторяющейся задачи при выполнении рассчитывается следующая дата

## Выполненные задания повышенной сложности

* настройка порта сервера через переменную окружения `TODO_PORT`;
* настройка пути к файлу SQLite через переменную окружения `TODO_DBFILE`;
* поддержка дополнительных правил повторения `w` и `m`;
* поиск задач по тексту в заголовке и комментарии, а также по дате

Аутентификация и Docker-образ в текущей версии проекта не реализованы

## Запуск

### Требования

* Go 1.25 или новее

Версия Go указана в `go.mod`. Дополнительная ручная установка зависимостей не требуется: Go использует файлы `go.mod` и `go.sum`

### Локальный запуск

Из корневой директории проекта выполните:

```bash
go run .
```

При стандартных настройках приложение использует файл SQLite-базы:

```text
scheduler.db
```

Если файла ещё нет, он будет создан при запуске

По умолчанию сервер работает на порту `7540`. После запуска откройте в браузере:

```text
http://localhost:7540
```

### Переменные окружения

Приложение поддерживает две необязательные переменные окружения:

| Переменная    | Назначение         | Значение по умолчанию |
| ------------- | ------------------ | --------------------- |
| `TODO_PORT`   | порт HTTP-сервера  | `7540`                |
| `TODO_DBFILE` | путь к SQLite-базе | `scheduler.db`        |

Например, в macOS/Linux можно запустить приложение с другими настройками:

```bash
TODO_PORT=8080 TODO_DBFILE=/tmp/todo-scheduler.db go run .
```

После этого интерфейс будет доступен по адресу:

```text
http://localhost:8080
```

Файл `.env` проектом не используется

## Тестирование

Перед запуском тестов необходимо запустить веб-сервер

В `tests/settings.go` для текущей версии проекта используются следующие значения:

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = ``
```

Где:

* `Port` — порт запущенного сервера;
* `DBFile` — путь к SQLite-базе относительно директории `tests`;
* `FullNextDate = true` — включает проверку дополнительных правил повторения `w` и `m`;
* `Search = true` — включает проверку поиска;
* `Token` — остается пустым, поскольку аутентификация не реализована

Запустите сервер из корня проекта:

```bash
go run .
```

Затем в другом терминале, также из корня проекта, выполните полный набор тестов:

```bash
go test ./tests
```

> **Важно:** тесты изменяют содержимое указанной базы данных. В частности, тест списка задач очищает таблицу `scheduler` перед выполнением проверки. Не используйте для тестового запуска базу с данными, которые необходимо сохранить.

Для проекта также настроен GitHub Actions, который автоматически запускает проверки при отправке изменений в репозиторий
